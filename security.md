# Security Policy

We take the security of our software seriously, and we appreciate the efforts of security researchers and users who help us find and fix vulnerabilities.

This policy applies to all PCN repositories unless a repository has its own SECURITY file, in which case that one takes priority.

## Reporting a vulnerability

**Please do not report security vulnerabilities through public GitHub issues, discussions, or pull requests.**

Instead, email **security@pcn-inc.com** with:

- The affected repository and version
- A description of the vulnerability and its potential impact
- Steps to reproduce, or a proof of concept if you have one
- Any suggested fix or mitigation, if you have ideas

If you're a PCN customer with a support contract, you can also report issues through your usual support channel.

## What to expect

These projects are provided as-is and maintained on a best-effort basis, so we can't commit to specific response times. That said, we treat security reports as a priority. We'll aim to:

- Acknowledge your report as soon as we reasonably can
- Keep you informed as we investigate and work on a fix
- Credit you for the discovery when we publish a fix, unless you'd prefer to stay anonymous

## Supported versions

Unless a repository states otherwise, security fixes are applied to the latest release only. If you're running an older version, please upgrade before reporting.

## Disclosure

We ask that you give us a reasonable amount of time to investigate and address a vulnerability before disclosing it publicly. We'll work with you on timing and keep you in the loop.

We don't currently offer a bug bounty program, but we're genuinely grateful for responsible disclosure.
